## What You Are Building

A mobile-first, dark-mode personal organization web app.  
Six tabs. One user. No backend in Phase 1.  
All data persists to browser localStorage only.  
No Notion. No Google Calendar. No login. No cloud sync.  
Those come in later phases once the UI is validated.

The product answers one question fast:  
"What does today require from me, based on my routine and my tasks?"

---

## Tech Stack

- React 18 + Vite
- TypeScript
- Tailwind CSS (dark mode, mobile-first)
- localStorage via a typed lib/storage.ts wrapper
- Lucide React for icons
- No backend
- No external APIs in Phase 1

## TypeScript Types (types.ts)

```typescript
export type DayOfWeek =
  | "Sunday" | "Monday" | "Tuesday" | "Wednesday"
  | "Thursday" | "Friday" | "Saturday";

export type Task = {
  id: string;
  title: string;
  notes?: string;
  status: "backlog" | "today" | "done";
  priority?: "low" | "medium" | "high";
  category?: string;
  dueDate?: string;
  createdAt: string;
  completedAt?: string;
};

export type RoutineItem = {
  id: string;
  title: string;
  optional?: boolean;
};

export type RoutineTemplate = {
  id: string;
  dayOfWeek: DayOfWeek;
  name: string;
  items: RoutineItem[];
};

export type RoutineCompletion = {
  date: string;                    // ISO date string YYYY-MM-DD
  routineTemplateId: string;
  completedItemIds: string[];
};

export type Habit = {
  id: string;
  name: string;
  description?: string;
  colorTag?: string;
  active: boolean;
  createdAt: string;
};

export type HabitCompletion = {
  habitId: string;
  date: string;                    // ISO date string YYYY-MM-DD
};

export type CalendarEvent = {
  id: string;
  title: string;
  start: string;                   // ISO datetime string
  end?: string;
  allDay?: boolean;
  source: "manual" | "google";
  location?: string;
};
```

## Page Specs

### Home (Home.tsx)

Primary content (always visible):
- Greeting: "Good [morning/afternoon/evening], Kieran" based on time of day
- Today's date (e.g., "Monday, June 21")
- Today's routine checklist (pulled from RoutineTemplate matching today's DayOfWeek; items are checkable inline; shares state with Routines tab)
- Upcoming calendar events (next 3 events from CalendarEvent[], sorted by start time)

"More" section (collapsed by default, tap to expand):
- Today's habit completion status
- Count of today's active tasks
- Streak or progress summary (e.g., "3 of 5 habits done today")
- A rotating motivational quote (hardcoded array of 10 to 20 quotes, no external API)

Behavior:
- Routine check state resets at midnight (compare completion date to today's ISO date string)
- Tapping a calendar event opens a modal with event details
- Home tab pulls data from shared AppContext, does not duplicate state

---

### Routines (Routines.tsx)

Day-of-week pill selector at top: Sun Mon Tue Wed Thu Fri Sat  
Today's day pre-selected on open.

For each selected day:
- Display the RoutineTemplate for that day
- Checklist of RoutineItem[] with tap-to-complete behavior
- Edit mode (pencil icon or long press): add, remove, reorder items
- Reorder via drag or up/down arrow buttons (drag-and-drop is optional)
- Changes to templates save immediately to localStorage
- Completion state is tracked separately from the template (RoutineCompletion by date)

Empty state (no routine for that day):
- "No routine set for [day]. Tap + to build one."

---

### Habits (Habits.tsx)

List of active Habit[] with:
- Tap-to-toggle completion circle for today (stores HabitCompletion)
- Habit name + optional description
- Streak counter: count of consecutive days with HabitCompletion records
- Color dot matching colorTag

Weekly grid below each habit:
- 7 circles representing the last 7 days
- Filled = completed, hollow = missed
- Labels: S M T W T F S

FAB to add a new habit. Add habit form:
- Name (required)
- Description (optional)
- Color tag (pick from 6 preset options)

Long press on a habit to edit or deactivate (soft delete: sets `active: false`).

---

### Calendar (Calendar.tsx)

Month grid view (default).  
Tap a day to expand the day's event list below the grid.  
Events shown as color-coded dots on grid days.

Event list for selected day:
- All-day events at top
- Timed events sorted by start time
- Title + start time

FAB to add a manual event. Add event form:
- Title (required)
- Date (required)
- Start time (optional)
- End time (optional)
- All-day toggle
- Location (optional)

Structure the CalendarEvent type and fetch function so that Phase 1.5 can replace manual events with Google Calendar data by swapping the data source, not rewriting the component.

Note: `source: "google"` events will be read-only. Add a guard: if `event.source === "google"`, hide the edit/delete controls. This lets the two sources coexist in Phase 1.5.

---

### To-Do (Todo.tsx)

Active task list for today. Filters Tasks where `status === "today"`.

Task card:
- Title
- Priority badge (color-coded: red = high, yellow = medium, no badge = low)
- Tap to complete (sets `status: "done"` and `completedAt`)
- Swipe left or long-press for delete (confirm with undo toast)
- Swipe right or long-press for "Send to Backlog" (sets `status: "backlog"`)

Completed tasks:
- Collapse into a "Done today" section at the bottom
- Strike-through + dimmed, not removed from view

FAB to add a task (adds directly to today, `status: "today"`).

---

### Backlog (Backlog.tsx)

Tasks where `status === "backlog"`.

Task card:
- Title
- Priority badge
- Swipe right or tap "Send to Today" button: sets `status: "today"`, sets due date to today
- Swipe left or long-press: delete with undo toast

Search bar at top (filter by keyword, client-side only).  
Sort options: Date added / Priority / Title (toggle, persists to localStorage).

FAB to add to backlog. Add task form:
- Title (required)
- Notes (optional)
- Priority (select)
- Category (optional text field)
